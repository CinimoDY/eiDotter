# Tree-shakable icon library with dual-audience (public curated + private full)

## Context

eidotter is a public, CC-BY-NC-licensed design system whose Figma source contains 1,172 icons, but only ~43 are production-ready. One repo needs to serve two audiences at once: npm consumers who should see a curated, tree-shakable public set, and the maintainer who wants the full catalog available locally for exploration and promotion decisions. The library must tree-shake cleanly in Vite, Webpack, Next.js, and raw Node ESM — with component CSS side effects still preserved.

## Guidance

The pattern has five coordinated subsystems. Each is ordinary on its own; the leverage comes from wiring them together.

### 1. Package exports: three entry points, one wildcard

Expose a curated barrel, a full barrel, and a deep subpath for per-icon imports. The wildcard subpath is what makes full tree-shaking work without any barrel overhead.

```json
{
  "sideEffects": ["**/*.css", "**/*.scss"],
  "exports": {
    ".":            { "import": "./dist/index.es.js",            "types": "./dist/index.d.ts" },
    "./icons":      { "import": "./dist/icons/published.js",     "types": "./dist/icons/published.d.ts" },
    "./icons/all":  { "import": "./dist/icons/index.js",         "types": "./dist/icons/index.d.ts" },
    "./icons/*":    { "import": "./dist/icons/components/*.js",  "types": "./dist/icons/components/*.d.ts" }
  },
  "files": ["dist", "dist/icons"]
}
```

Scope `sideEffects` to stylesheets only. Setting `false` globally would let bundlers strip `import './Button.css'` inside non-icon components and silently break styles in production.

### 2. Split tsconfig for the icons project

Icons use the automatic JSX runtime so each generated TSX file can skip `import React`. The main library uses classic JSX. Mixing runtimes in one tsc pass forces an unwanted trade-off, so give icons their own project.

```json
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "jsx": "react-jsx",
    "module": "ES2020",
    "moduleResolution": "bundler",
    "isolatedModules": true,
    "rootDir": "src/icons",
    "outDir": "dist/icons",
    "declaration": true,
    "declarationMap": true,
    "noEmit": false,
    "emitDeclarationOnly": false
  },
  "include": ["src/icons/**/*"]
}
```

Exclude `src/icons` from the main `tsconfig.build.json` so its classic-runtime pass skips the generated TSX. Build sequence: `vite build && tsc -p tsconfig.build.json && tsc -p tsconfig.icons.json`.

### 3. Barrels emit explicit `.js` extensions

Barrel generators write `.js` in the source so Node-ESM consumers resolve correctly after tsc emit. TypeScript still resolves these to the underlying `.ts` files at compile time.

```ts
// src/icons/published.ts (generated)
export type { IconComponent, IconSvgProps } from './types.js';
export { AlertTriangle } from './components/alert-triangle.js';
export { Check }         from './components/check.js';
// ... one line per manifest entry
```

`src/icons/index.ts` (full barrel) is generated by **scanning the filesystem**, so it automatically matches whatever is checked out: 43 files on fresh clones, 1,172 files on the maintainer's machine. No conditional logic, no branching.

### 4. Gitignore with a script-managed negation block

One directory, two worldviews. Glob-ignore all icon components, then re-include the curated ones via `!` negations managed by the barrel generator.

```gitignore
src/icons/components/*.tsx
src/icons/index.ts
scripts/icons/.cache/

# >>> BEGIN CURATED ICONS (auto-generated) <<<
# Curated icons stay in git; the rest is ignored.
# Edit src/icons/published.manifest.json then run `npm run generate-icons`.
!src/icons/components/alert-triangle.tsx
!src/icons/components/check.tsx
# ... one line per manifest entry
# >>> END CURATED ICONS <<<
```

**Critical detail:** the marker contains parentheses (`(auto-generated)`). Escape them before constructing the `RegExp` that rewrites the block — otherwise they parse as regex capture groups and the replacement silently fails to match on re-runs.

```js
const escapeRegex = s => s.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
const BEGIN = '# >>> BEGIN CURATED ICONS (auto-generated) <<<';
const END   = '# >>> END CURATED ICONS <<<';
gitignore = gitignore.replace(
  new RegExp(`${escapeRegex(BEGIN)}[\\s\\S]*?${escapeRegex(END)}`),
  () => curatedBlock,
);
```

### 5. Pipeline: fetch → build TSX → build barrels

Three small, idempotent scripts:

- `scripts/icons/fetch-svgs.mjs` — Figma REST API (token from `.env`) → `.cache/svgs.json`
- `scripts/icons/build-tsx.mjs` — extract `<path d="…"/>` → one `IconComponent`-typed TSX per icon
- `scripts/icons/build-barrels.mjs` — reads `published.manifest.json`, scans the filesystem, writes `published.ts` + `index.ts`, and rewrites the `.gitignore` negation block

Adding an icon to production is one edit: append a name to `src/icons/published.manifest.json`, run `npm run generate-icons`. The manifest, barrels, and `.gitignore` stay in lockstep automatically.

### TSX component template

Generated components use the automatic runtime, pass props through, and support an accessible `title`:

```tsx
import type { FC } from 'react';
import type { IconSvgProps } from '../types.js';

export const AlertTriangle: FC<IconSvgProps> = ({ size = 24, title, ...props }) => (
  <svg
    width={size}
    height={size}
    viewBox="0 0 24 24"
    fill="currentColor"
    xmlns="http://www.w3.org/2000/svg"
    role={title ? 'img' : undefined}
    aria-hidden={title ? undefined : true}
    {...props}
  >
    {title ? <title>{title}</title> : null}
    <path d="…" />
  </svg>
);
```

## Why This Matters

**Why not `sideEffects: false`?** Component CSS imports (`import './Button.css'`) would be stripped. Scoping to `**/*.css` preserves styles while letting icon modules tree-shake.

**Why not commit all 1,172 files?** The repo is public on GitHub. Exposing experimental or unreviewed icons implies a support contract we don't want to offer and inflates clones for contributors who only need the curated set.

**Why not publish all and document only curated?** npm tree-shaking is probabilistic across bundlers. IDE autocomplete, type-driven docs, and bundle analyzers would surface experimental names as first-class API even if unmentioned in README.

**Why not use svgr?** A 40-line custom generator gives exact control over the `IconComponent` type, `size`/`title` props, and `aria-*` wiring. Configuring svgr templates for these edge cases is more code than writing the transform directly, and adds a dependency.

**Why not one tsconfig with `jsx: "react-jsx"` everywhere?** That's a breaking change for the main library's emitted `.d.ts` and requires revisiting every consumer that relied on the classic runtime. The split is one extra file — a small price for isolation.

**Why not a single barrel?** Deep subpath imports (`eidotter/icons/heart`) skip the barrel entirely. This is the only shape that guarantees zero-overhead tree-shaking across bundlers that don't fully honor `sideEffects` hints.

**Why a dynamic, filesystem-scanning full barrel?** On fresh clones (43 icons), `index.ts` must not reference 1,129 missing files. On the maintainer's machine (1,172 icons), `index.ts` should expose everything. A dynamic scan satisfies both without branching logic.

**Why explicit `.js` extensions?** Node's strict ESM refuses extension-less imports at runtime. Emitting `from './components/foo.js'` directly in TypeScript source keeps the package Node-ESM-compatible without bundler-only assumptions — TS still resolves the path to `./components/foo.tsx` during compilation.

## When to Apply

- Design-system or icon-library repo is **public** but contains private/experimental assets that should not ship.
- Icon count is **large enough that tree-shaking matters** (~100+) and barrel-only imports would bloat consumer bundles.
- The asset set has a **curated core plus an experimental long tail** with different quality bars.
- Consumers span **multiple bundlers** (Vite, Webpack, Next.js, raw Node ESM) — you can't rely on one bundler's tree-shake heuristics.
- You control the **generation pipeline** (Figma → SVG → TSX) and can afford one manifest file as the curation boundary.

## Examples

**Curated import (default audience, small bundle):**

```tsx
import { AlertTriangle, Check } from 'eidotter/icons';

export const Toolbar = () => (
  <>
    <AlertTriangle size={16} title="Warning" />
    <Check size={16} />
  </>
);
```

**Full-set import (maintainer / power user, opt-in):**

```tsx
import { Activity } from 'eidotter/icons/all';
// Resolves from dist/icons/index.js, which only exists when the full
// catalog is present. On a fresh public clone, this barrel lists 43 names;
// locally, 1,172.
```

**Deep subpath (maximal tree-shaking, bundler-agnostic):**

```tsx
import { Heart } from 'eidotter/icons/heart';
// No barrel traversal. Even bundlers that ignore sideEffects ship only
// heart.js and its transitive deps.
```

## Prevention

- **Smoke tests on the barrels** — assert (a) components dir has >N files, (b) every file on disk is re-exported from `index.ts`, (c) every manifest entry has a corresponding file, (d) every barrel import uses an explicit `.js` extension. See `src/icons/__tests__/barrels.test.ts`.
- **Escape marker strings before regex use** — anything with `(`, `)`, `.`, `*`, `+`, `?` etc. in the literal marker will silently break the rewrite. Use a small `escapeRegex` helper.
- **Don't couple the generator to Figma session state** — use the REST API with a token, not a websocket plugin, so regeneration is a single command (`npm run fetch-icons && npm run generate-icons`).
