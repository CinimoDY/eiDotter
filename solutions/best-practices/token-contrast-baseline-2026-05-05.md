# Token contrast baseline (Pass 1 — Accessibility Audit Phase 1)

WCAG 2.1 contrast measurements for every semantic token foreground/background pair, across all five themes. Generated by `scripts/check-contrast.mjs`. Raw data in `token-contrast-baseline-2026-05-05.json`.

## Method

Each theme overrides `--color-cga-*` primitives **and** re-maps `--color-semantic-*` → primitive for that theme. The script:

1. Loads `src/styles/tokens.css` (default mappings) plus the theme file (theme-specific overrides).
2. Resolves each `--color-semantic-{text,border,background}-*` to a final hex.
3. Computes WCAG 2.1 relative luminance and contrast ratio for every foreground × background pair.
4. Reports pass/fail at AA body (≥4.5:1), AA large (≥3:1), AAA body (≥7:1).

Limitation: tokens that resolve to `rgba()` with alpha are reported as `unresolved` because the script does not alpha-blend against the underlying background. This affects `text-muted` in the three CGA Mode 4 / Mode 5 themes — see "Open question" at the bottom.

## Verdict by theme

### `amber-mono` (default theme)

**Passes WCAG AA for every valid usage.** All bright-on-dark pairs land 11–14:1. The "failures" in the raw table are all one of:

- Same-token-on-same-token (e.g. `text-primary` on `background-accent` when both resolve to `#ffb000`) — these aren't valid usages and never appear in components.
- `text-secondary` on `background-primary`/`secondary` — contractually disallowed per `CLAUDE.md` ("only use `text-secondary` on amber/light backgrounds"). When used correctly (`text-secondary` on `background-accent`), it's 11.42:1.
- Disabled tokens — WCAG 2.1 SC 1.4.3 exempts inactive UI components from contrast minimums.

| FG → BG (valid usages only) | Hex pair | Ratio | AA body | AA large |
|---|---|---|---|---|
| text-primary → bg-primary | #ffb000 / #020003 | 11.42 | ✅ | ✅ |
| text-primary → bg-secondary | #ffb000 / #010103 | 11.38 | ✅ | ✅ |
| text-secondary → bg-accent | #020003 / #ffb000 | 11.42 | ✅ | ✅ |
| text-accent → bg-primary | #e5b936 / #020003 | 11.28 | ✅ | ✅ |
| text-muted → bg-primary | #b87c1a / #020003 | 5.91 | ✅ | ✅ |
| text-ai-draft → bg-primary | #ff1a8c / #020003 | 5.76 | ✅ | ✅ |
| border-focus → bg-primary | #fdca9f / #020003 | 14.07 | ✅ | ✅ |

### `cga-amber`

**Real AA gaps when content lands on `background-secondary` (`#5a5852` warm mid-gray).** The amber palette's secondary background is much lighter than amber-mono's near-black, which collapses contrast for several tokens.

| FG → BG | Ratio | AA body | Severity |
|---|---|---|---|
| text-primary → bg-secondary (#adaaa5/#5a5852) | 3.07 | ❌ | **High** — typical body text |
| text-accent → bg-secondary (#ffb000/#5a5852) | 3.88 | ❌ (PASS large) | Medium |
| text-muted → bg-primary (#aa5500/#050300) | 3.93 | ❌ (PASS large) | Medium |
| text-muted → bg-secondary (#aa5500/#5a5852) | 1.36 | ❌ | **High** if used |
| text-ai-draft → bg-secondary (#ff1a8c/#5a5852) | 1.96 | ❌ | Medium |
| border-default → bg-secondary | 3.07 | ❌ (PASS large) | Low (non-text) |

bg-primary pairings all pass AA body except `text-muted` (3.93) and disabled (exempt).

### `cga-mode4-p0` (CGA Mode 4 Palette 0 — black/green/red/yellow)

**Passes AA for every text-on-background-primary/secondary pair** (15–19:1 because the palette is high-saturation primary colors on near-black). `text-muted` cannot be evaluated because it resolves to `rgba(255,255,0,0.65)` with alpha.

Flags:
- `text-ai-draft → bg-accent` (#ff1a8c/#00ff00): 2.65 — AI-marker pink fights against bright green accent. Not surprising; AI marker is brand-locked.
- `text-disabled → bg-accent` (#ff0000/#00ff00): 2.91 — exempt (disabled).

### `cga-mode4-p1` (cyan/magenta/white)

Same shape as `mode4-p0`: all primary/secondary pairs pass strongly (16–20:1). `text-muted` unresolved (alpha).

Flags:
- `text-ai-draft → bg-accent` (#ff1a8c/#00ffff): 2.90 — AI-marker on cyan accent.

### `cga-mode5`

Identical results to `cga-mode4-p1` — same accent (cyan) and same primary/secondary stack.

## Cross-theme summary

| Issue | Themes affected | Severity |
|---|---|---|
| `text-primary` on `background-secondary` fails AA body | cga-amber only | **High** |
| `text-muted` on `background-primary` borderline (3.9:1) | cga-amber | Medium |
| `text-ai-draft` (Signalnoise pink) on bright accents fails | all themes when accent is bright | Medium (intentional brand-lock) |
| `text-muted` is `rgba()` with alpha in 3 themes | mode4-p0, mode4-p1, mode5 | **Open question** — see below |
| Disabled tokens fail AA — exempt by WCAG 1.4.3 | all themes | Documented exemption |

## Recommendations (for follow-up plan, not this audit)

1. **`cga-amber` `background-secondary` (`#5a5852`) is too light.** Either darken it (closer to `#2a2925`) or re-map the affected text tokens to higher-contrast primitives in this theme only. The default amber-mono uses `#010103` for `bg-secondary` — much safer.
2. **`text-muted` alpha decision.** The mode4/mode5 themes use `rgba(...)/0.65` for muted. This is opaque to static analysis and to consumers reading the token. Either resolve to a flat hex per theme (preferred), or document the alpha + the assumed background.
3. **`text-ai-draft` brand lock.** `#ff1a8c` cannot pass on bright accent backgrounds. Document in `ACCESSIBILITY.md` that AI-draft prose is intended for body text on dark backgrounds only, and skip the marker (or use an alt indicator) when the prose lands on an accent.
4. **`text-disabled` documentation.** WCAG exempts disabled UI from contrast requirements but consumers still need to know. Add a note in `TOKENS.md` linking to SC 1.4.3.

## Re-running

```bash
node scripts/check-contrast.mjs              # human-readable table
node scripts/check-contrast.mjs --json       # machine-readable
node scripts/check-contrast.mjs --theme cga-amber
```

Exit code is always 0 — this is a reporting tool. A future plan may add a `lint-contrast` mode that fails the build on regressions.

## Open question

`text-muted` in `cga-mode4-p0`, `cga-mode4-p1`, `cga-mode5` resolves to an `rgba()` value with `alpha=0.65`. The script does not alpha-blend, so contrast is reported as `unresolved`. Verifying these requires either:

- (a) Resolving the alpha against each `background-*` token to a synthetic hex and computing contrast on that.
- (b) Replacing the alpha-bearing tokens with flat hex equivalents per theme (matches amber-mono's pattern).

Recommend (b) in the follow-up token-contrast remediation plan.
