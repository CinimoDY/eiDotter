# Upgrading to eidotter 0.46.0

From 0.45.x. Coming from older versions, read the earlier guides first
([0.41.0](./0.41.0.md), [0.43.0](./0.43.0.md), [0.44.0](./0.44.0.md),
[0.45.0](./0.45.0.md)).

0.46.0 makes text one size, moves the page column to the left edge, and adds
the shared header control and theme helpers.

## Who must act

- Everyone: check pages after the bump; most components now set smaller text (section 2).
- Apps on `PageShell` or `Header contained`: the column is no longer centred (section 3).
- Apps with `sticky={false}` headers: the header now shows the page's ground (section 4).
- Apps with a theme switch or ⌘K hint in the header: move to `DisplayMenu` + `HeaderButton` + the theme helpers (section 5).

## 1. How to bump

```bash
npm install eidotter@^0.46.0
npm ls eidotter   # 0.46.0 or later
```

Commit the lockfile.

## 2. Visible: one body size

**What changed.** All non-heading text in every component is 16px
(`text-dos-text-base`). It used to run 18 to 26px depending on component and
size: Button md was 22px, Badge and Tag 18 to 22px, Select options 20px, the
MENU trigger 20px, timeline cards 18 to 22px, health-family labels 18 to
22px. Size props (`size="lg"` and so on) now change only height, padding and
gap. Headings and display numbers (the values of Stat, Gauge and
VitalsStrip) keep their larger sizes. The DosDialog strip title (Modal,
Lightbox, CmdPalette) is 16px too, like the DosWindow strip. `Progress`
`size` no longer changes the bar, which is made of text glyphs.

**What to do.**

- Look at pages with buttons, badges, tags, forms and timelines. Things are
  smaller and denser; that is the intended look.
- Do not set font sizes on eidotter components to get the old look back.
  Under the DOS themes the one body size is the standard; keep it.
- Your own text: use `text-dos-text-base` for body text. The global
  `.dos-body*` utility classes still carry the older sizes in 0.46.

**How to verify.** In dev tools, component text (outside headings and big
numbers) computes to 16px.

## 3. Visible: the page column is flush left

**What changed.** `PageShell`'s column starts at the left gutter instead of
being centred, and runs to a 1200px cap. Text inside (intro, paragraphs,
lists, section titles, an embedded LegalPage) keeps an 80-column measure
(45rem). Wide blocks (Bench, tables, galleries, card grids) may use the full
cap from the same left edge. `Header contained` follows: flush left, 1200px
cap. The layout is the same in every theme.

**What to do.**

- Nothing, if you use PageShell and `Header contained` as they are.
- Pages that centred their own column next to an eidotter header: drop the
  `margin-inline: auto` so the content and the header share the left edge.
- `PageShell maxWidth` still sets the cap.

## 4. Visible: a non-sticky Header has no ground of its own

With `sticky={false}` the Header is transparent, so a CRT tint,
`RetroEffects` or the amber-paper ground shows through. A sticky Header keeps
its opaque ground so content scrolls under it. If a sticky header's ground
should match a tinted page, set that colour on it with a class.

## 5. New: HeaderButton and the display theme helpers

**HeaderButton** is the one shape for header controls (36px, 32px on phones).
DisplayMenu's trigger is one; use it for a ⌘K launcher so both match:

```tsx
import { HeaderButton } from 'eidotter';

<HeaderButton aria-label="Open command palette" onPress={() => setPaletteOpen(true)}>⌘K</HeaderButton>
```

Show the ⌘K launcher from 480px up: phones have no ⌘ key, and at 320px a
lockup brand, two controls and MENU do not fit.

**Theme helpers.** Labels are DOS (style: DOS or modern) and LIGHT
(brightness; under DOS it is the `amber-paper` theme). Options that do not
apply in the current mode are hidden, never shown disabled.

```tsx
import { DisplayMenu, displayMenuItems, resolveDisplayTheme, syncThemeColor } from 'eidotter';

const themes = { modernLight: 'light' };            // omit for a DOS-only site
const [state, setState] = useState({ dos: true, light: false });

useEffect(() => {
  document.documentElement.dataset.theme = resolveDisplayTheme(state, themes);
  syncThemeColor();                                  // phone status bar follows the theme
}, [state]);

<Header end={<DisplayMenu label="Theme" items={displayMenuItems(state, setState, themes)} />} … />
```

Call `syncThemeColor()` on load and after every switch; never render the
`theme-color` meta in JSX (React resets its content on re-render).

## 6. amber-paper polish

Muted, secondary and tertiary text are deeper (8.3:1 on the ground). No glow
behind the Logo and Mark. Tabs rows scroll inside themselves when too wide.
DosWindow titles ellipsize inside narrow cards.

## Checklist

- [ ] `npm install eidotter@^0.46.0`; `npm ls eidotter` shows 0.46.0 or later. Commit the lockfile.
- [ ] Pages look right with the one body size; no font-size overrides on eidotter components (section 2).
- [ ] Content and header share the left edge; no centred columns of your own next to them (section 3).
- [ ] Non-sticky headers over tinted pages look right (section 4).
- [ ] Header controls: one `DisplayMenu` built with `displayMenuItems`, ⌘K as a `HeaderButton` from 480px up, `syncThemeColor()` on load and on every switch (section 5).
