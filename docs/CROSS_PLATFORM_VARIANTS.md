# Cross-Platform Variants

How eiDotter delivers tokens across web and Apple platforms, and how consuming projects should adopt them.

## Current State

eiDotter generates tokens for four platforms from a single source (`src/tokens/base.tokens.json`):

| Output | Format | Consumers |
|--------|--------|-----------|
| `tokens.css` | CSS custom properties | Rizomorf, eidotter-home |
| `tokens.js` / `tokens.json` | JavaScript/JSON | Build tools, Storybook |
| `tailwind.preset.js` | Tailwind CSS preset | Rizomorf, eidotter-home |
| `EiDotterTokens.swift` | Swift enums (SwiftUI `Color`, `CGFloat`) | Spacewar ATV (planned), DOSBTS (planned) |

### The Gap

Spacewar ATV's `AmberTheme.swift` hardcodes values instead of consuming `EiDotterTokens.swift`:

```swift
// Current (hardcoded) — Spacewar ATV
static let amber = SKColor(red: 1.0, green: 191.0 / 255.0, blue: 0, alpha: 1.0) // #FFBF00
static let fontName = "Perfect DOS VGA 437"

// Target (token-driven) — should become
static let amber = EiDotterColors.colorCgaAmber  // same value, single source
```

This document defines the strategy for closing that gap.

## Platform Adaptation Strategy

### Principle: Override Aesthetic, Respect Interaction

eiDotter's visual identity (CGA palette, monospace type, hard edges, phosphor glow) transfers to every platform. Platform interaction conventions do not.

| Layer | eiDotter Owns | Platform Owns |
|-------|---------------|---------------|
| Color | CGA palette, semantic mapping | Dark mode API integration |
| Typography | JetBrains Mono / DOS VGA font | Dynamic Type scaling (iOS) |
| Spacing | 4px grid values | Safe area insets, system margins |
| Shape | 4px max border radius | Platform control shapes (toggles, sliders) |
| Animation | Phosphor warmup/energize | Platform transitions (navigation, sheets) |
| Interaction | Visual feedback (glow, flash) | Gesture handling, haptics, focus engine |

### What This Means in Practice

**Override:** Background colors, text colors, border styles, font family, glow effects, border radius. These define the CGA aesthetic and must be consistent.

**Adapt:** Touch target sizes (44pt minimum on iOS), Dynamic Type support, system navigation patterns, tvOS focus engine behavior, safe area handling. Fighting the platform here creates a worse experience.

**Ignore:** `prefers-color-scheme` (eiDotter is dark-only), system accent colors, default tint colors, system fonts.

**Do not touch:** iOS scroll physics, keyboard avoidance, system alerts/sheets (tint them, don't replace them).

### Override/Adapt Decision Table

| Domain | Approach | Rationale |
|--------|----------|-----------|
| Color palette | Override | The whole point of the design system |
| Border radius | Override | 0–4px is non-negotiable for DOS |
| Typography face | Override | JetBrains Mono is the brand |
| Typography sizing | Adapt | Anchor to Dynamic Type for accessibility |
| Touch targets | Adapt | 44pt minimum is a usability requirement |
| Navigation chrome | Adapt | Fight `UINavigationBar` and lose |
| Shadows/glow | Override | Hard shadows + phosphor glow = the aesthetic |
| Color scheme | Override to dark | No light mode for a CRT terminal |
| Animations | Override + reduce motion | CRT effects are the brand, but accessibility first |
| System sheets/alerts | Adapt (tint only) | System sheets should feel native |
| Scroll physics | Do not touch | iOS scroll is sacred |
| Keyboard avoidance | Do not touch | System handles this correctly |

## Web Platform (CSS + Tailwind)

The primary platform. All tokens available as CSS custom properties and Tailwind utilities.

### Token Consumption

```css
/* Direct CSS variable usage */
background: var(--color-semantic-background-primary);
color: var(--color-semantic-text-primary);
font-family: var(--typography-font-family-primary);

/* Tailwind utility classes */
<div class="bg-dos-bg-primary text-dos-text-primary font-dos">
```

### Theme Switching

Import a theme CSS file and set `data-theme` on any container:

```css
@import "eidotter/themes/amber-mono.css";
```

```html
<div data-theme="amber-mono">
  <!-- all semantic tokens resolve to amber shades -->
</div>
```

Five themes available: `amber-mono`, `cga-amber`, `cga-mode4-p0`, `cga-mode4-p1`, `cga-mode5`.

## iOS / SwiftUI Platform

### Token File: EiDotterTokens.swift

Three enums generated by Style Dictionary:

```swift
EiDotterColors      // SwiftUI Color values (CGA + semantic + effects)
EiDotterSpacing     // CGFloat values on 4px grid
EiDotterTypography  // CGFloat font sizes
```

### App Setup: Force Dark Mode

A CGA terminal has no light mode. Lock the entire app to dark:

```swift
@main
struct DOSBTSApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
                .preferredColorScheme(.dark)
        }
    }
}
```

### Convenience Extensions (Recommended)

Add these to consuming projects for ergonomic token access:

```swift
// MARK: - Font

extension Font {
    /// eiDotter font with Dynamic Type scaling
    static func eiDotter(size: CGFloat, relativeTo style: Font.TextStyle = .body) -> Font {
        .custom("JetBrainsMono-Regular", size: size, relativeTo: style)
    }
    /// eiDotter bold with Dynamic Type scaling
    static func eiDotterBold(size: CGFloat, relativeTo style: Font.TextStyle = .body) -> Font {
        .custom("JetBrainsMono-Bold", size: size, relativeTo: style)
    }
}

// MARK: - DOS Surface

struct EiDotterSurface: ViewModifier {
    func body(content: Content) -> some View {
        content
            .clipShape(RoundedRectangle(cornerRadius: 2))
            .overlay(
                RoundedRectangle(cornerRadius: 2)
                    .stroke(EiDotterColors.colorSemanticBorderDefault, lineWidth: 1)
            )
    }
}

// MARK: - Glow

extension View {
    func eiDotterDropShadow() -> some View {
        self.shadow(color: .black, radius: 0, x: 2, y: 2)
    }

    func eiDotterGlow(radius: CGFloat = 10) -> some View {
        self
            .shadow(color: EiDotterColors.colorCgaAmberGlow, radius: radius)
            .shadow(color: EiDotterColors.colorCgaAmberGlow, radius: radius * 2)
    }
}
```

### Consuming Tokens in SwiftUI

```swift
import SwiftUI

struct DOSButton: View {
    let label: String

    var body: some View {
        Text(label)
            .font(.eiDotter(size: EiDotterTypography.fontSizeBase))
            .foregroundColor(EiDotterColors.colorSemanticTextPrimary)
            .padding(.horizontal, EiDotterSpacing.sp4)
            .padding(.vertical, EiDotterSpacing.sp2)
            .background(EiDotterColors.colorSemanticBackgroundAccent)
            .clipShape(RoundedRectangle(cornerRadius: 4))
            .frame(minHeight: 44) // iOS touch target (visual size unchanged)
    }
}
```

### Consuming Tokens in SpriteKit (tvOS)

Spacewar ATV uses SpriteKit, not SwiftUI. SpriteKit requires `SKColor` (which is `UIColor` on iOS/tvOS). The bridge:

```swift
import SpriteKit

extension EiDotterColors {
    /// Convert SwiftUI Color to SKColor for SpriteKit usage
    static func skColor(_ color: Color) -> SKColor {
        SKColor(color)
    }
}

// Usage in Spacewar
let amberSK = EiDotterColors.skColor(.init(
    red: 1.0, green: 0.690, blue: 0.0, opacity: 1.0
))
```

**Better approach:** Add `SKColor` / `UIColor` constants directly to `EiDotterTokens.swift` via a Style Dictionary transform. This avoids runtime conversion:

```swift
// Future: dual output in EiDotterTokens.swift
public enum EiDotterColors {
    // SwiftUI
    public static let colorCgaAmber = Color(red: 1.000, green: 0.690, blue: 0.000, opacity: 1.000)

    // UIKit / SpriteKit
    public static let colorCgaAmberUI = UIColor(red: 1.000, green: 0.690, blue: 0.000, alpha: 1.000)
}
```

### Dynamic Type Consideration

iOS users expect text to scale with their accessibility settings. eiDotter uses fixed font sizes — this is intentional for the CRT aesthetic but creates a conflict on iOS.

**Recommended approach:** Support Dynamic Type scaling for body text while keeping display/UI text fixed:

```swift
// Body text: scales with Dynamic Type
Text(content)
    .font(.custom("JetBrains Mono", size: EiDotterTypography.fontSizeBase, relativeTo: .body))

// UI labels: fixed size (buttons, badges, HUD)
Text(label)
    .font(.custom("JetBrains Mono", fixedSize: EiDotterTypography.fontSizeSm))
```

The `relativeTo:` parameter lets iOS scale the custom font proportionally to the user's text size preference. Fixed sizes stay constant regardless of settings.

### Phosphor Glow on iOS

Web uses `box-shadow` for phosphor glow. iOS equivalent:

```swift
// SwiftUI shadow for phosphor glow
Text("READY")
    .shadow(color: EiDotterColors.colorCgaAmberGlow, radius: 10)
    .shadow(color: EiDotterColors.colorCgaAmberGlow, radius: 20) // layered bloom

// SpriteKit glow via SKEffectNode
let glowNode = SKEffectNode()
glowNode.shouldRasterize = true
glowNode.filter = CIFilter(name: "CIGaussianBlur", parameters: ["inputRadius": 8.0])
```

### Reduced Motion on iOS

Respect `accessibilityReduceMotion` for all CRT effects — this mirrors the web's `prefers-reduced-motion` handling:

```swift
@Environment(\.accessibilityReduceMotion) var reduceMotion

Text("READY")
    .shadow(
        color: reduceMotion ? .clear : EiDotterColors.colorCgaAmberGlow,
        radius: 10
    )
```

### tvOS Focus Engine

tvOS uses a focus engine instead of touch. The focus system highlights the focused element — this maps naturally to eiDotter's phosphor warmup pattern:

```swift
struct DOSButton: View {
    @Environment(\.isFocused) var isFocused

    var body: some View {
        Text(label)
            .foregroundColor(EiDotterColors.colorSemanticTextPrimary)
            .shadow(
                color: isFocused ? EiDotterColors.colorCgaAmberGlow : .clear,
                radius: isFocused ? 12 : 0
            )
            .scaleEffect(isFocused ? 1.05 : 1.0)
            .animation(.easeInOut(duration: 0.2), value: isFocused)
    }
}
```

## Theme Support on iOS

Web themes work through CSS custom property cascading. Swift has no equivalent mechanism. Two approaches:

### Option A: Build-Time Themes (Current)

`EiDotterTokens.swift` is generated from `base.tokens.json`, which uses the amber-mono theme. To support other themes, generate separate Swift files per theme:

```
EiDotterTokens.swift           # amber-mono (default)
EiDotterTokens+CGAAmber.swift  # cga-amber overrides
EiDotterTokens+Mode4P0.swift   # cga-mode4-p0 overrides
```

Apps import the theme they need. Simple but inflexible.

### Option B: Runtime Theme Switching (Future)

Create a theme provider that swaps token values at runtime:

```swift
class EiDotterTheme: ObservableObject {
    @Published var current: ThemeTokens = .amberMono

    enum ThemeTokens {
        case amberMono, cgaAmber, cgaMode4P0, cgaMode4P1, cgaMode5

        var textPrimary: Color {
            switch self {
            case .amberMono: return Color(red: 0.722, green: 0.486, blue: 0.102)
            case .cgaAmber: return Color(red: 1.0, green: 0.690, blue: 0.0)
            // ...
            }
        }
    }
}

// Usage
struct ContentView: View {
    @EnvironmentObject var theme: EiDotterTheme

    var body: some View {
        Text("Hello")
            .foregroundColor(theme.current.textPrimary)
    }
}
```

**Recommendation:** Start with Option A. Spacewar and DOSBTS only need amber-mono. Add runtime switching when a consumer actually needs it.

## Migration Guide: Spacewar ATV

Replace `AmberTheme.swift` hardcoded values with `EiDotterTokens.swift`:

| Before (AmberTheme) | After (EiDotterTokens) |
|---------------------|----------------------|
| `SKColor(red: 1.0, green: 191/255, blue: 0, alpha: 1)` | `EiDotterColors.colorCgaAmber` |
| `SKColor.black` | `EiDotterColors.colorCgaBlack` |
| `SKColor(red: 170/255, green: 136/255, blue: 0, alpha: 1)` | `EiDotterColors.colorCgaAmberDim` |
| `"Perfect DOS VGA 437"` | Keep as-is (font name is platform-specific, not tokenized) |
| `fontSizeLogo: 192` | Keep as-is (tvOS sizes are scaled for 10-foot viewing, different from token sizes) |

**Note:** Font names and tvOS-specific sizes stay in `AmberTheme.swift`. Only colors and standard spacing migrate to tokens. tvOS viewing-distance scaling is a platform concern, not a design system concern.

### Steps

1. Add `EiDotterTokens.swift` to Spacewar ATV's Xcode project
2. Import and replace color references in `AmberTheme.swift`
3. Keep font name and tvOS-scaled font sizes local
4. Verify colors match visually (amber values differ slightly: `#FFBF00` vs `#FFB000`)

**Color discrepancy:** Spacewar uses `#FFBF00` (BF), tokens output `#FFB000` (B0). These are close but not identical. The token value (`#FFB000`) is the canonical P3 phosphor amber. Spacewar should adopt the token value.

## Token Pipeline Integration

### How It Works Today

```
src/tokens/base.tokens.json
    ↓ Style Dictionary
    ├── tokens.css           (CSS custom properties)
    ├── tokens.js            (JavaScript module)
    ├── tokens.json          (Raw JSON)
    ├── tailwind.preset.js   (Tailwind preset)
    ├── EiDotterTokens.swift (Swift enums)
    └── theme.*.css          (5 theme overlays)
```

All outputs are generated by `npm run build-tokens`. Edit JSON sources, never edit outputs.

### Adding UIColor/SKColor Output

To support SpriteKit without runtime conversion, add a custom Style Dictionary format that outputs `UIColor` alongside `SwiftUI.Color`:

```js
// In style-dictionary.config.mjs
swift: {
  transformGroup: 'ios-swift',
  buildPath: 'src/styles/',
  files: [{
    destination: 'EiDotterTokens.swift',
    format: 'ios-swift/enum.swift',
    // Future: custom format that outputs both Color and UIColor
  }]
}
```

This is a future enhancement — tracked separately from this document.

## Summary

| Decision | Rationale |
|----------|-----------|
| Override colors, type, shape, glow | These define the CGA identity |
| Adapt touch targets, Dynamic Type, navigation | Platform conventions improve usability |
| Build-time themes first | Only amber-mono needed today |
| Token colors as source of truth | Eliminates hardcoded hex drift |
| Keep tvOS font sizes local | Viewing-distance scaling is platform-specific |
| Font names stay platform-specific | Different platforms use different font formats |
| Force `.preferredColorScheme(.dark)` | CRT terminals have no light mode |
| Use `relativeTo:` for body fonts | Dynamic Type scaling is an accessibility bridge |
| 44pt min touch targets on iOS | Pad the tap area, not the visual element |
| Respect `accessibilityReduceMotion` | Mirrors web `prefers-reduced-motion` pattern |

## Future: Swift Package Distribution

When DOSBTS needs tokens as a dependency, ship `EiDotterTokens.swift` plus font files as a Swift Package:

```
EiDotterTokens/
  Sources/
    EiDotterTokens/
      Colors.swift
      Spacing.swift
      Typography.swift
  Resources/
    JetBrainsMono-Regular.ttf
    JetBrainsMono-Bold.ttf
  Package.swift
```

Token updates ship as package version bumps. Consuming apps get type-safe access with build-time validation.

An alternative: generate `.xcassets` color sets via Style Dictionary. Xcode 15+ auto-generates typed accessors (`Color(.eiDotterBackgroundPrimary)`) that fail at compile time if a token is removed.
