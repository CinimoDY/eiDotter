# Safely deprecating a package.json subpath export

## Context

A published npm package's `exports` map is part of its public API contract. Removing a subpath entry causes `require('pkg/subpath')` and `import 'pkg/subpath'` to throw `ERR_PACKAGE_PATH_NOT_EXPORTED` at load time — before any application code runs. This is a hard break that consumers cannot work around without editing their configs.

**Concrete incident.** eidotter [PR #282](https://github.com/CinimoDY/eiDotter/pull/282) ("Merge Tailwind presets into one", merged 2026-04-18 as `07f5f6b`, DMNC-681) consolidated `tailwind.preset.js`, `tailwind.preset.cjs`, and `tailwind.preset.enhanced.cjs` into one auto-generated `tailwind.preset.cjs`. As a side effect the PR **deleted** `tailwind.preset.enhanced.cjs`, removed `"./tailwind.preset.enhanced": "./tailwind.preset.enhanced.cjs"` from `package.json` `exports`, and removed the file from `files[]`. Shipped as patch `0.19.1`. The prior README explicitly instructed consumers to `require('eidotter/tailwind.preset.enhanced')`, so every consumer following that README upgraded straight into a Tailwind build failure.

Post-merge [ce:review](https://linear.app/lizomorf/issue/DMNC-712) flagged this P1 across three reviewers (api-contract, project-standards, agent-native). [PR #283](https://github.com/CinimoDY/eiDotter/pull/283) (merged 2026-04-18 as `1367cfc`) shipped the recovery as a 22-line deprecation shim and a patch bump to `0.19.2`. The pattern below generalizes that recovery.

## Guidance

### 1. Never delete a subpath in a patch/minor — add a shim instead

When the underlying implementation goes away (file merged, renamed, consolidated), keep the published subpath alive as a **tiny hand-written file** that re-exports the new target:

```js
// tailwind.preset.enhanced.cjs  (hand-written shim, NOT generated)

/**
 * Deprecated alias for `eidotter/tailwind.preset`.
 *
 * REMOVE-IN-0.21.0 — grep this marker when preparing the 0.21.0 release to
 * delete this file, the `./tailwind.preset.enhanced` entry in `package.json`
 * `exports`, and the matching entry in `files`.
 *
 * @note Hand-written — NOT generated by `style-dictionary.config.mjs`.
 *       The sibling `tailwind.preset.cjs` IS generated; do not confuse them.
 */

if (!globalThis.__eidotterEnhancedPresetDeprecationWarned) {
  globalThis.__eidotterEnhancedPresetDeprecationWarned = true;
  console.warn(
    "[eidotter] 'eidotter/tailwind.preset.enhanced' is deprecated since 0.19.2 " +
      "and will be removed in 0.21.0. Use 'eidotter/tailwind.preset' instead."
  );
}

// Direct re-assignment (not a spread) — preserves object identity so
// `require('eidotter/tailwind.preset.enhanced') === require('eidotter/tailwind.preset')`.
// A spread would shallow-copy and break any tooling that memoizes by identity.
module.exports = require('./tailwind.preset.cjs');
```

### 2. Keep `exports` and `files` paired

The shim file isn't reachable unless both entries exist:

```diff
 "exports": {
   "./tailwind.preset": "./tailwind.preset.cjs",
+  "./tailwind.preset.enhanced": "./tailwind.preset.enhanced.cjs",
 },
 "files": [
   "tailwind.preset.cjs",
+  "tailwind.preset.enhanced.cjs",
 ]
```

`npm pack --dry-run` catches a missing `files[]` entry.

### 3. Use `globalThis` — not a module-local `let` — for once-per-process warnings

```js
// CORRECT — survives require.cache invalidation
if (!globalThis.__eidotterEnhancedPresetDeprecationWarned) {
  globalThis.__eidotterEnhancedPresetDeprecationWarned = true;
  console.warn('[eidotter] ...deprecated...');
}

// WRONG — resets when the module is re-required after cache clear
let warned = false;
if (!warned) { warned = true; console.warn(...); }
```

Dev servers, test runners, and bundler plugins all invalidate and re-require modules. A module-local `let warned` fires on every re-require — spammy and untrustworthy as a "happens exactly once" signal. `globalThis` with a namespaced key (`__<package><Flag>Warned`) survives cache resets. Verified empirically: `require` → `delete require.cache[...]` → `require` emits the warn exactly once.

### 4. Leave a `REMOVE-IN-<version>` grep marker

A deprecation shim with no scheduled removal lives forever. Every shim should contain an unambiguous, greppable string:

```
REMOVE-IN-0.21.0
```

Add a release-prep step: `grep -r "REMOVE-IN-$NEXT_VERSION" .` before cutting the version. Three surfaces should agree on the removal target:
- JSDoc `@deprecated since X.Y.Z — will be removed in A.B.C`
- Runtime `console.warn` message
- CHANGELOG `### Deprecated` entry

### 5. Classify the version bump correctly

**Fixing an unintentionally-shipped break is a patch bump**, even though the fix restores an entry point:

- `0.19.0` → `0.19.1` (the accidental break)
- `0.19.1` → `0.19.2` (shim restored)

Verify the broken version was actually published before classifying — `npm view <pkg>@<version>` confirms whether the regression reached real consumers. If the removal hasn't been published yet, the cleanup rolls into the same version (not a new one).

Under strict SemVer, deliberately removing a subpath is a **major** bump. A shim lets you downgrade what would be a major break into a minor deprecation.

### 6. Write a CHANGELOG entry that shows the diff consumers need

```markdown
## [0.19.2] - 2026-04-18

### Deprecated
- **Tailwind preset:** `eidotter/tailwind.preset.enhanced` is now a deprecated alias for `eidotter/tailwind.preset` and will be removed in 0.21.0. Consumers should migrate to the single preset import:
  ```diff
  - presets: [require('eidotter/tailwind.preset.enhanced')]
  + presets: [require('eidotter/tailwind.preset')]
  ```
  The shim logs a one-time `console.warn` on load. No behavior change — the merged preset already carries the React Aria state variants and animate plugin that the enhanced preset used to add.
```

`### Deprecated` is the Keep-a-Changelog subsection for this case (not `### Changed` or `### Removed`). Include the consumer-pastable diff inline.

### 7. Update every consumer-facing doc in the same PR

When the public surface changes, the CHANGELOG alone is not enough. *(auto memory [claude])* This project's standing rule: any release or consumer-setup change must touch `README.md`, `CLAUDE.md`, `guidelines/README.md`, and — for design-system-style docs — `ADOPTION_STRATEGY.md` in lockstep.

PR #282 partially violated this (stale `tailwind.preset.js` in `ADOPTION_STRATEGY.md`). PR #283 caught the straggler plus a stale `CLAUDE.md` "One preset is exported" line that had become wrong the moment the shim was restored.

### Common mistakes (what to avoid)

- **Shipping the deletion under a patch with no shim and no CHANGELOG.** The original incident in PR #282. Any consumer following the prior README upgraded straight into `ERR_PACKAGE_PATH_NOT_EXPORTED`.
- **Module-local `let warned = false`** for memoization. Does not survive `delete require.cache[...]` + re-require.
- **Deleting without a `REMOVE-IN-<version>` marker.** Shims without a scheduled removal accumulate forever.
- **Forgetting `files[]`.** `exports` entries pointing at files that aren't published still fail at install-time.
- **Assuming the subpath is unused.** Grep the library's own monorepo, but also assume at least one external consumer followed the old README. Shim first, remove later.
- **Bundling the CHANGELOG update without the README/docs update.** The README is what consumers read during install — it must match the new contract.

## Why This Matters

- **`exports` is a load-time contract.** Unlike a deprecated function that still runs, a missing subpath throws before your code executes. There is no graceful degradation, no feature flag, no runtime check the consumer can add. The build simply fails.
- **SemVer patches imply safety.** Consumers use `^0.19.0` or `~0.19.1` expecting patch upgrades to be drop-in. A patch that removes a published subpath silently violates that expectation and corrupts `npm audit fix`, Dependabot, and Renovate automation.
- **Shims cost ~30 lines and buy months of migration time.** The shim adds one `require.cache` indirection (negligible — same object graph), emits a single warn per process, and gives consumers a clear migration path. Cost is essentially zero; value is every downstream project not having a broken build on upgrade morning.
- **Post-merge review is the safety net.** In the incident, ce:review flagged the issue P1 across three reviewer personas (api-contract, project-standards, agent-native). When a PR slips past self-review, structured post-merge review catches it before the mistake compounds.

## When to Apply

Apply this pattern whenever you are about to:

- Delete a `package.json` `exports` subpath that was previously published
- Merge two exports into one (the incident's case — `tailwind.preset.enhanced` folded into `tailwind.preset`)
- Rename a published entry point (old name becomes the shim, new name becomes the target)
- Change what a subpath resolves to in a backward-incompatible way
- Remove a file from `files[]` that is referenced by any `exports` entry

**Skip the shim only if:**
- The subpath was never published (verify with `npm view <pkg> versions`)
- You are already cutting a major version AND have a documented migration guide AND have notified known consumers

## Examples

### The break (PR #282)

```diff
# package.json (under a 0.19.0 → 0.19.1 patch)
 "exports": {
   "./tailwind.preset": "./tailwind.preset.cjs",
-  "./tailwind.preset.enhanced": "./tailwind.preset.enhanced.cjs",
 },
 "files": [
   "tailwind.preset.cjs",
-  "tailwind.preset.enhanced.cjs",
 ]
```

```
$ rm tailwind.preset.enhanced.cjs
$ git commit -m "feat: merge Tailwind presets into single generated file"
# no CHANGELOG note, no shim, no deprecation warning
# README still instructs: require('eidotter/tailwind.preset.enhanced')
```

Consumer result after `npm update`:

```
Error [ERR_PACKAGE_PATH_NOT_EXPORTED]: Package subpath './tailwind.preset.enhanced'
is not defined by "exports" in /node_modules/eidotter/package.json
```

### The recovery (PR #283)

Shipped as patch `0.19.1` → `0.19.2`:

1. **Hand-written shim** at `tailwind.preset.enhanced.cjs` (see Guidance §1)
2. **Restore `package.json` entries** — `exports` + `files` (see Guidance §2)
3. **CHANGELOG entry under `### Deprecated`** with consumer-pastable diff (see Guidance §6)
4. **Doc updates in the same PR** — `README.md`, `CLAUDE.md`, `ADOPTION_STRATEGY.md`

Consumer result after `npm update` to `0.19.2`:

```
[eidotter] 'eidotter/tailwind.preset.enhanced' is deprecated since 0.19.2
and will be removed in 0.21.0. Use 'eidotter/tailwind.preset' instead.
# (printed once per process, build succeeds, zero config change required)
```

`0.21.0` preparation: `grep -r "REMOVE-IN-0.21.0" .` finds the shim, the `package.json` export, and the `files[]` entry — all deleted together under the planned release that the warn message advertised.
