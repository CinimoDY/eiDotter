# Token Parity · eiDotter Design System handoff (April 2026)

The design team delivered a handoff bundle (`eiDotter Design System-handoff.zip`)
with a token sheet (`colors_and_type.css`) and Figma "Value" mode type scale
(`Value.tokens.json`). This Storybook section is a **visual-only** parity view
between what the repo currently ships and what the handoff proposes.

## Reading this section

- **Identical categories are not rendered.** The CGA 16-color primitives,
  amber family, color-glow washes, spacing (4px grid), radius, border widths,
  shadow drop + glow scales (xs/sm/md/lg + colored variants), motion durations,
  and the `--fx-*` CRT effect rgba values **all match byte-for-byte** already.
  Nothing to see.
- **Divergent categories get a side-by-side story.** Each sibling story
  renders one divergence (T1–T11) with the repo's current value on the left
  and the handoff's proposed value on the right. Hex / rgba labels are copy-able
  from the DOM.
- **No repo tokens are edited.** Handoff values are rendered via inline styles
  or scoped CSS strings inside the story modules. The repo's
  `src/tokens/*.json` → `src/styles/tokens.css` pipeline is untouched.

## How to decide

Most divergences fall in one of three buckets:

1. **Low-risk + warmth-aligned** (T1–T6, T11) — safe to adopt as a small
   token PR. Visual diff is subtle on T2/T4/T5/T6, more noticeable on T1/T3/T11.
2. **Philosophy-level** (T9, T10) — require team alignment. Adopting means
   "hierarchy only via color/case/underline, never weight, and muted = dim
   amber". Fine if the library commits to single-weight bitmap fonts; flag if
   the existing Flexi/JetBrains fallback chain relies on weight variants.
3. **Breaking** (T7, partially T8) — warrant a coordinated version bump and
   consumer migration plan (codemod to rename `base` → `md`, etc.). Defer.

Nothing is adopted automatically. This view is the decision tool; adoption
lives in a follow-up plan.
