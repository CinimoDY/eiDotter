# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 0.3.x   | :white_check_mark: |
| < 0.3   | :x:                |

## Reporting a Vulnerability

We take security seriously. If you discover a security vulnerability in eidotter, please report it responsibly.

### How to Report

**Please do NOT report security vulnerabilities through public GitHub issues.**

Instead, please report them via email to: **eidotter@cinimody.com**

Include the following information in your report:

- Description of the vulnerability
- Steps to reproduce the issue
- Potential impact
- Any suggested fixes (optional)

### What to Expect

- **Acknowledgment**: We will acknowledge receipt of your report within 48 hours.
- **Assessment**: We will assess the vulnerability and determine its severity.
- **Updates**: We will keep you informed of our progress.
- **Resolution**: We aim to resolve critical vulnerabilities within 7 days.
- **Credit**: With your permission, we will credit you in our security advisories.

### Scope

This security policy applies to the eidotter npm package and its official repository.

**In scope:**
- Security issues in the eidotter library code
- Vulnerabilities in dependencies that affect eidotter
- Security issues in build/release process

**Out of scope:**
- Issues in applications using eidotter (report to those projects)
- Social engineering attacks
- Denial of service attacks

## Security Best Practices for Users

When using eidotter in your projects:

1. **Keep updated**: Always use the latest version of eidotter
2. **Check dependencies**: Run `npm audit` regularly
3. **Review changes**: Check the CHANGELOG before updating major versions
